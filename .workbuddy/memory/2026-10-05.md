用户找人修的，我审查后**结论：全部正确，修的都是我上一轮实现的真实缺陷**。

### SQLite 存储的九个缺陷（我原来的问题）

| 修复 | 我原来的 bug |
|---|---|
| 逐行读 + 反序列化前检查字节预算 | **预读 256 条**才判预算 |
| `recent_before` 委托 bounded(.., usize::MAX) | 两份重复查询逻辑 |
| 初始化失败**明确退出** | 静默退回内存 → **用户以为有历史其实没有** |
| 反序列化失败**向上传播** | 静默跳过损坏记录 |
| 启动时也裁剪 | **反复重启可绕过保留策略** |
| 裁剪失败保留计数 | 无条件清零 → 要等 1000 条才重试 |
| `sql_timestamp()` 查 i64 范围 | `as i64` **溢出静默截断** |
| SQLite 走 `spawn_blocking` | async 上下文里跑同步 IO，**阻塞运行时** |
| 裁剪边界 `<=`（原 `<`） | **差一条**（`OFFSET N` 拿到的正是该删的） |

→ **教训：`as i64` 这类转换、`if let Ok(..)` 这类静默吞错、同步 IO 放 async 里，
都是"看起来没问题但会在边界上炸"的写法。**

## 主题改造（`67dbfa1`）—— 用户反馈"首屏黑色然后瞬间切白"

### 用户是对的，而且比反馈的更严重

- `<html data-theme="dark">` **硬编码**，偏好要等 `main.js`（加载 wasm，几百 ms）才应用
  → 首屏**必然**先画深色再跳浅色（FOUC）
- 默认值写死 `'dark'`，**`prefers-color-scheme` 全仓没用过**

### 改法

1. **`index.html` 加同步内联脚本**（**在所有 CSS 之前**），首帧前定主题
2. `store.js` 默认 `'dark'` → **`'auto'`**
3. `theme.js` 重写：`auto`/`dark`/`light` 三态，监听 `matchMedia` change
   （**只在该跟的时候跟**，不覆盖用户选择）
4. 设置页：开关 → **三选一 select**

### ★ 自愈兜底（重要）

`init()` 不盲目信任内联脚本 —— **重算并比对，不一致就纠正**。
理由：内联脚本可能没跑（CSP 禁止内联、缓存旧 HTML、剥离脚本的扩展），
此时"只读 DOM"会让页面**永远停在错误主题**。

### ★ 测试的关键设计

`scripts/e2e/theme.mjs`（14 项）判定的是"**观测值有没有变过**"（时序），
**不是"最终值对不对"** —— 旧的闪烁版本最终值也对，只看最终值永远测不出来。

**对照实验**：把 `index.html` 临时改回旧写法 → `FLASH dark→light`，
证明测试真的能抓到闪烁（不是假绿）。**这个手法值得复用**。

### 踩到的坑

- **属性撞名**：`<html>` 上的 `data-theme-pref` 与设置页
  `<select data-theme-pref>` 撞名 → `querySelector` 返回 `<html>` 而不是 select。
  → 改名 `data-theme-setting`。
- `select.options` 是 `HTMLOptionsCollection`（类数组），**不能用展开运算符**，
  要 `Array.from`。
- **`page.selectOption` 不能用**：`onchange` 触发 `render()` 整段重建面板，
  Playwright 缓存的元素引用失效 → 超时。改成**派发 `change` 事件**。
- `[data-x] option` 是**选择器分组**，会匹配页面上**所有** select 的 option。
