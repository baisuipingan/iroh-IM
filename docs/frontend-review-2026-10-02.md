# 前端 Review 报告（2026-10-02）

环境：Chrome CDP + 本地 `scripts/dev-serve.py`（127.0.0.1:8099），
两个标签页各用 `?testid=1`（随机身份）模拟两个真实 peer，走自建 iroh 中继。

结论：**消息收发是真的**（gossip + QUIC over relay，端到端跑通），
但围绕它的状态管理有一批"看起来能用、实际是假"的实现。以下 15 项都已定位到
具体文件行、给出根因，并已修好。

---

## 一、真 bug（会导致数据丢失或功能不可用）

### 1. 中文输入法按 Enter 选词 = 误发送拼音缓冲 【严重】

- **位置**：`js/ui/composer.js` init 里的 keydown 处理器
- **现象**：拼音打到一半按 Enter（上屏选词）→ 整段拼音被当作消息发出去。
  实测 `isComposing:true` 的 Enter 被 `preventDefault()` 吞掉并触发 `send()`，
  对端真的收到了 `nihao`。
- **根因**：只判断了 `e.key === 'Enter' && !e.shiftKey`，没判断 IME 组字态。
  组字期间的 Enter 语义是"选词"而不是"发送"。
- **修复**：keydown 里加 `if (e.isComposing || e.keyCode === 229) return;`，
  另加 `compositionend` 同步一次按钮状态。
  同类问题在 `js/ui/dialog.js` 的 Enter 确认（改昵称/房间名时按选词键会把对话框直接关掉），
  一并修掉。

### 2. 发送失败 = 用户的输入凭空消失 【严重】

- **位置**：`js/ui/composer.js` `send()`
- **现象**：`input.value = ''` 在 `await net.send()` **之前**无条件执行。
  离线或节点无响应时，文字直接没了，只在底部闪一行 tip。
- **根因**：把"清空输入框"当成发送的起手式，而不是发送**成功**后的收尾。
- **修复**：改成"成功才清空"；失败时把原文写回输入框，
  并在时间线上落一个**标红的失败气泡**（带失败原因 + 「重新发送」/「删除」）。
  `timeline.pushFailed()` 落地，`.msg--failed` 那条 CSS 终于有了对应的状态
  （之前是死样式，全项目没有任何代码用它）。重发成功后自动撤掉失败气泡。

### 3. 会话列表重渲染 = 滚动位置归零

- **位置**：`js/ui/sidebar.js` `render()`
- **现象**：列表滚到中间时，任意一条新消息触发 `render()` → 整个
  `#panel-body` 的 `innerHTML` 被替换 → `scrollTop` 变 0，视图跳回顶部。
- **根因**：`innerHTML` 替换会连带丢掉容器的滚动状态，代码没有保存/恢复。
- **修复**：替换前记住 `scrollTop`，替换后还原。

### 4. 会话预览与未读数只存在内存里，刷新即全部丢失

- **位置**：`js/ui/sidebar.js` 的 `previews` / `unread` 两个 `Map`
- **现象**：明明有人发过消息，刷新后列表却显示"还没有消息"、未读红点消失。
  这正是"假数据"的观感来源。
- **根因**：两个状态是纯内存 `Map`，没有任何持久化。
- **修复**：`js/store.js` 新增 `previews` / `unread` 两个 localStorage 键
  （含条数上限，和房间列表的 40 条一致），`sidebar` 启动时恢复、变更时写盘，
  「清除本地记录」也一并清掉。

### 5. 收到新消息不会把会话顶到最前

- **位置**：`js/ui/sidebar.js` 的 `EV.MSG` 处理器
- **现象**：在别的房间发消息，被顶下去的那个会话顺序不动。
- **根因**：`store.upsertRoom(room, { last: ... })` 只在 `openRoom()` 里调用，
  消息事件只更新了 `previews` 没更新 `last`，而排序键就是 `last`。
- **修复**：消息事件和 `EV.HISTORY` 都用消息时间戳更新 `room.last`。

### 6. 完全没有重连机制，且离线后 UI 仍在骗人 【严重】

- **位置**：`js/net.js` `_dispatch()` 的 `relayStatus` 分支
- **现象**：所有中继断开时，只把文案改成"离线"，`this.ready` 仍为 `true`。
  于是输入框照常可打字、按钮照常可点，点了必失败，而且**永远不会自愈**。
- **根因**：把"连接状态"当成只读展示，没有状态机，也没有重试。
- **修复**：引入 `phase`（`starting` / `online` / `reconnecting` / `offline`）+ `canSend`：
  - 退避重连 1s→2s→4s→8s→15s→30s 封顶，`_scheduleRetry()` 统一调度；
  - 监听 `online` 事件，网络一恢复立刻重试，不等计时器；
  - 重连成功后自动 `join` 回断开前的房间并发 `EV.REJOINED`；
  - 断线时输入区**禁用**并给出原因 placeholder，工具条按钮一起灰掉
    （之前只禁用了 textarea，图标还能点）；
  - 状态胶囊可点 = 手动重连；侧栏状态页加「立即重新连接」行。

### 7. 移动端选完房间，聊天区被面板完全遮住且无法关闭 【严重】

- **位置**：`css/layout.css` 的 `@media (max-width: 760px)`
- **现象**：390×844 下点某个会话 → 列表仍盖在聊天区上面，
  聊天内容一点都看不到，也没有任何返回手段（面板是 `position:absolute` 覆盖层）。
- **根因**：`is-open` 只有加没有摘 —— `sidebar.show()` 加了它，
  选中房间的路径里没人调关闭；`.panel` 也没有点击外部关闭的遮罩。
- **修复**：新增 `#panel-scrim` 遮罩层（点它关闭）+ `sidebar.closePanel()`，
  移动端点会话后自动收起面板；面板移出屏幕时加 `visibility:hidden`（否则
  `transform` 移走的元素仍可被点击）。顺带补了移动端触控尺寸
  （行高 44px、工具钮 36px、待发送缩略图 64px、表情面板贴边、气泡放宽到 86%）。

## 二、状态不完整 / 逻辑不自洽

### 8. 「回到最新」按钮写死 `bottom: 152px`

- **位置**：`css/components.css` `.jump-btn`
- **现象**：待发送区展开（附件多）时，按钮直接压在输入框上（实测重叠 14px）。
- **根因**：数值写死，而 composer 高度是动态的。
- **修复**：改用 CSS 变量 `--composer-h`，由 `timeline.syncJumpBtn()` 用
  `ResizeObserver` 量出来实时写入。

### 9. 空房间没有任何空态

- **位置**：`js/ui/timeline.js` `loadLatest()`
- **现象**：进到一个没人说话的房间，时间线完全空白（连提示都没有），
  用户不知道是"坏了"还是"真的没人说话"。
- **修复**：新增 `.tl-empty` 空态（图标 + 说明 + 怎么邀请对方），
  第一条消息到达时自动移除。历史加载失败也从"只弹 tip"改成
  **可重试**的行内提示。

### 10. 系统提示永久累积

- **位置**：`js/ui/timeline.js` `note()`
- **现象**：每进一次房间就留两条"正在进入「x」…" / "已进入「x」"，
  切几次房间时间线上就是一堆假系统消息。
- **根因**：`note()` 每次都 `appendChild`，从不清理。
- **修复**：改成**单例 slot**——同一条替换、非 sticky 的 6 秒后自动淡出。
  任何时刻最多一条系统提示。

### 11. 常驻节点在成员列表里出现两次

- **位置**：`js/ui/sidebar.js` `view_people()`
- **现象**："在线成员"里有一条 `5bcc4ea3`，下面的"常驻节点"又是同一个 `5bcc4ea3`。
- **根因**：anchor 本身就是一个真实端点，会出现在 `peers` 里，
  而"常驻节点"分区又无条件画了一遍。
- **修复**：从"在线成员"里过滤掉 anchor id，只在"常驻节点"分区呈现，并标注是否已连接。

### 12. 节点启动失败 = 一行 innerHTML，且没有任何自救入口

- **位置**：`main.js` `main()` 的 catch
- **现象**：一行红字，用户只能手动刷新。
- **修复**：改成结构化的失败态（标题 + 原因 + 可能原因说明 + 「重新启动节点」按钮），
  并把状态胶囊也置为失败态。

### 13. 翻页时把分隔线状态覆盖成旧值

- **位置**：`js/ui/timeline.js` `prependPage()`
- **现象**：向上翻页后，接下来收到的新消息会拿一个**错误的时间基准**
  判断要不要插时间分隔（可能多插或漏插一条）。
- **根因**：`lastDayKey` / `lastTs` 描述的是"视口里最新那条消息的位置"，
  但前插时顺着遍历直接覆盖了它们。
- **修复**：进入时保存、结束时还原；顺带让历史页内部也按 5 分钟分组
  （之前一页 50 条全挤在一起没有时间参照）。
  另外 `loadLatest` / `loadOlder` 都加了"期间切了房间就丢弃结果"的守卫 ——
  之前慢返回的历史会串到当前房间里。

### 14. 底部提示永不消失

- **位置**：`js/ui/composer.js` `tip()`
- **现象**："连接中继超时（15s）"会一直挂着，恢复后也不清，
  看起来像"仍然有问题"。
- **修复**：5 秒自动消失 + 同文案去重 + 按文案自动判别是否用错误色
  （`失败|出错|错误|超时|不可达`）。

## 三、微信视觉一致性

### 15. 气泡缺尖角；`.msg--hist` 让整屏发灰；会话预览多一个"我:"前缀

- **位置**：`css/components.css`、`js/ui/sidebar.js` `view_chats()`
- **问题**：
  - 气泡只有 `border-*-radius: 2px` 假装有尖角，没有真正的三角形；
  - `.msg--hist .bubble { opacity: .85 }` 让**回看历史时整屏发灰**，
    而微信里历史和刚到的消息是同一种颜色；
  - 会话预览渲染成 `我: xxx` / `昵称: xxx`，微信不写"我:"，靠气泡左右区分说话人。
- **修复**：用零宽高 + `border-*-color` 画真尖角（贴气泡靠头像那侧，
  文件卡/失败气泡不画）；去掉 history 的透明度；预览去掉前缀。
  踩坑记录：三角方向别搞反 —— 向左的尖角要给 `border-left-color`，
  给成 `border-right-color` 会变成向右，两侧都朝内等于没画（第一版就错在这）。

## 验证方式

全部在浏览器里实际点/打字验证，不是静态推演：

- **真双端收发**：两个标签页独立身份，B 发 → A 收 → A 回 → B 收，双向通过。
- **IME**：构造 `isComposing:true` 的 Enter 事件，确认不再被吞（修复前实测发出去了）。
- **发送失败**：拦截 worker RPC 让 `send` 抛错，确认输入框保留原文、
  出现红色失败气泡 + 原因 + 两个按钮；恢复后点「重新发送」成功，失败气泡消失。
- **断线重连**：注入 `relayStatus: 全部 disconnected` 并让 `online()` 挂起，
  观察状态胶囊/输入区/提示文案三者一致；恢复后确认自动重新进入原房间。
- **列表滚动**：滚到中部后由另一房间的消息触发重渲染，`scrollTop` 保持不变。
- **移动端**：390×844 实机点选会话，确认面板收起、聊天可见。
- **分页**：55 条消息的房间，向上滚触发翻页，条数 50→55，视口不跳。
- **清空 localStorage 后全新启动**无 console 错误。

## 已知未做（明确说明，不假装有）

- 语音消息仍是"还没做"的占位（`tb-voice` 会如实弹窗说明）。
- 没有"离开房间"入口：`net` 层没有 `leave` RPC，Worker 侧也没有对应实现，
  本次没有凭空加一个假的。
- 文件传输链路本次未做端到端压测（改动集中在消息/状态/UI 层，未触碰
  `filetransfer.js` 的传输逻辑，只让它新增的空态/失败态能正确渲染）。
- 中继探测的 RTT 在跨域下拿不到明细（缺 `Timing-Allow-Origin`），
  这是既有限制，本次只把"还在探 / 探完挂了"两种状态区分开，没改探测算法。
