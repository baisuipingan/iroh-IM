# 2026-10-12 A 期：邀请制召唤器（A2）+ 一房一会话结论（A3）+ 花名册成员状态（A4）

## 一句话

房间里 **@ 一个注册过但不在场的 agent**，召唤器会把它拉进房间、并在它出现在名册后用
规范 token `@<id8>` 把请求重说一遍；花名册同时显示每个成员的**状态（在线 / 忙碌 / 离线）**——
离线的人可以一键 @（房间里有召唤器时，发送即把人叫回来）。

## A2 · 召唤器（`agent-pi/src/summoner.ts`）

- **谁提供**：agent **所有者**在自己的机器上跑（凭据/沙箱在那边）。召唤器本身是房间里的
  普通成员（默认昵称"召唤器"，`respondToAll` 看所有消息，过滤在它自己内部做）。
- **谁有权**：v1 = 房间内任何成员；`--summon-from <id8,…>` 可收窄。**无论如何只能召唤
  注册表里列出的名字**（不能召唤任意程序）。
- **闸门**：`--max-live` / `--cooldown-ms` / `--idle-ms` / `--summon-from` / 注册表。
  全部超限**如实说一句**（"刚被叫过 N 秒后再试"/"最多带 N 个"/"没把你加进召唤名单"），不静默丢弃。
- **两条寻址**：`@注册名`（人手打的；名字后不接 ASCII 字母/数字/下划线，CJK 可直接接）与
  `@<id8>`（回复旧消息/空闲后再叫；id8→名字对照表从名册懒学习，不持久化；转交时用
  **它当前在名册里的** id8，换身份也命中）。
- **转交（relay）**：被拉进来的人看不到 @ 它的旧消息（gossip 不补历史）⇒ 等它出现在**名册**里，
  再用规范 token 重说一遍。
- 空闲回收看**互动**（没人叫、它也没说话），不是"进程活着"——长任务把 `--idle-ms` 调大。

用法（所有者侧；成员的 env 要带齐中继+rendezvous/history，样例见 `scripts/e2e/summoner.py`）：

```
node --experimental-strip-types agent-pi/src/summoner.ts \
  --rooms 房间名 --registry /path/registry.json --agent-bin /path/to/iroh-agent
```

> **本轮未把召唤器部署为常驻服务**：跑在谁家、能召唤谁、名单怎么收窄是产品决定（C4 治理）。
> 仓库给出实现与运行方式；服务化留给所有者按需启动。

## A3 · 一房一会话、按房串行（结论）

- **CLI 强制单房**：`--rooms a,b` 直接拒绝并说明原因——同一个 `IROH_AGENT_HOME`（身份目录）
  绝不能给两个 `serve` 进程共用（端点/中继会互相踢）。要同时盯多个房间 = 起多个召唤器进程，
  各自身份目录。
- **会话串行**：同一房间内，一轮未结束（或冷却窗口内）的新触发直接丢弃、不排队。

## A4 · 花名册成员状态（前端，零协议变更）

- **在线** = presence 软状态；**忙碌** = 名片标签里的约定「忙碌」（签名消息，天然进历史）；
  **离线** = 最近说过话但不在场（本地历史窗口推导，卡片上如实说明它不是权威名册）。
- 离线成员「@他」插入 `@昵称#id8` 草稿 → 发送前由 `resolveDraft` 归一成规范 token——
  房间里有召唤器时，A2×A4 闭环（发送即把人叫回来）。
- 名片编辑对话框里写明「忙碌」约定。

## 反漂移自检（方案 §8 逐条）

1. **房间只是场地，没变差**：是——没往房间塞任何工具/清单；召唤器的"注册表"是所有者本地文件，
   房间里只多了一个普通成员。
2. **昵称没被当寻址依据**：是——转交一律 `@<id8>`；昵称只用于"人打的 @"匹配与显示。
3. **加 agent = 加 spawn 配置**：是——注册表加一条即可，房间侧零改动。
4. **可单独回滚**：是——见上；回滚步骤已写。
5. **决策与现实冲突**：无。A3 的单房限制是本期**新披露的硬约束**（同一身份目录不能共用），
   已写进方案、CLI 错误信息与本文，不是静默改方向。
