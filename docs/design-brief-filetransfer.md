## 一、可直接复制的提示词

```
继续沿用「Bikini Bottom Nautical Desktop」这套设计语言（DESIGN.md 的调色板、字体、
圆角、阴影、字号一律不变），为这个 P2P 加密聊天室设计【文件与图片传输】模块。

这是本产品最重、也唯一还没设计过的核心模块。请**按状态穷举交付**，不要只给一张
"正常传输中"的理想图 —— 这个模块的全部难点都在异常态和多状态上。

必须覆盖的状态（每个状态都要出稿）：

【我是接收方】
 1. 等待你确认（收到别人发来的文件邀约）          主按钮 ✓接收  次按钮 ✗拒绝
 2. 传输中 + 进度条                                次按钮 ✗停止（已收内容会保留）
 3. 已暂停（可续传）                               按钮 ↻继续接收
 4. 接收中断（可继续）—— 刷新/关掉页面后恢复出来的  按钮 ↻继续接收
 5. 已完成（**不要画"打开文件"按钮**，我们保存后不持有文件句柄）
 6. 已拒绝
 7. 失败：<失败原因>
 8. 已失效
 9. 历史卡片三种变体：可接收（发送方在线）/ 检查中… / 已过期（发送方已离开）

【我是发送方 · 只发给一个人】
 1. 等待对方确认
 2. 传输中（**这张卡片上不要画总进度条** —— 我们的发送侧不显示总进度，
    进度只在"按接收者"的详情里。有自动化用例钉死这一点）
 3. 已发送，等待对方确认（数据发完、对方正在校验）
 4. 已完成
 5. 失败：<失败原因> → 出现「↻ 重新邀请」按钮（**只重邀失败/取消的人，
    不打扰已接收或已拒绝的人**）
 6. 已失效
 7. 已停止分享（文件被内存预算淘汰时会出现；**没有对应的用户操作按钮**，
    所以别画"停止分享"按钮）

【我是发送方 · 同时发给多个人】★ 这一组最重要
 一份文件发给 N 个人，**每个人独立接受/拒绝/失败，各自有独立进度**。
 需要设计：
 · 汇总行（一行说清 N 个人的结果），现有文案形如
   「已分享 · 2 人接收完成 · 1 人拒绝接收 · 1 人等待接收」
 · 可展开的「接收详情（N 人）」列表，每人一行：
   昵称 · id前6位 + 状态 + （传输中）该人**自己的**进度条 + （失败/取消）原因
   六种个人状态：等待接收 / 接收中 42% / 等待确认 / ✓已接收 / —已拒绝 / —已取消 / 接收失败
 · 收起态 / 展开态都要出稿，以及**展开后来了新进度不能自动折叠**

【环境约束】
 浏览器不支持接收（Firefox / Safari，收文件依赖 Chrome/Edge 的文件系统 API）
 → 卡片上显示「接收需 Chrome / Edge」+ 拒绝/移除

【图片】
 图片走同一条通道，但**视觉上必须看起来是"一张图"**，不是"一个叫 xxx.png 的文件"。
 必须给这 5 种极端比例出稿（我们的自动化会逐张量尺寸）：
 竖 600×900 / 方 480×480 / 横 900×450 / 超宽 1200×80 / 超高 80×1200
 另外要出：未接收时的占位框、预览已释放的文案态、
 以及点击图片后的全屏大图查看器。

【顺带（如果这一批方便）】
 · 把文件拖到窗口任意位置时的整窗投放提示层（文案：松开即可添加到待发送）
 · 输入框上方的"待发送区"（粘贴/拖拽/选择的文件先落在这里，可逐个 × 移除，
   可以配一段文字一起发 —— 微信的行为）

硬性尺寸约束（不要改，改了会挂自动化）：
 · 图片卡宽度 220px；未接收占位框高度 **116px**；已接收图片高度 **≤220px**
 · 文件卡 min-width 280px / max-width 380px，所在气泡最大宽度 84%
 · 左侧列表面板固定 **268px**（+ 最左图标栏 56px），聊天区在 1440 屏上约 1116px
 · 极窄屏（390px）下单列布局

交付要求：
 · 每个状态都要**浅色 + 深色**两套（深色是我们按同色相派生的，见 DESIGN.md 的说明）
 · 桌面 1440 与窄屏 390 都要看一遍
 · 格式同上一批：每个稿子一份 DESIGN.md + code.html + screen.png
 · 请额外出**一页状态矩阵**（状态 × 文案 × 按钮 × 进度），我们要拿它逐条对实现

明确不要做的：
 · 不要给状态编造我们拿不到的数据（比如"传输速度 2.4 MB/s""剩余 3 秒""排队第 2 位"
   —— 我们没有速率估算和排队概念）
 · 不要画我们做不到的交互（暂停后"从某秒继续播放"这种按时间轴的控制、多文件队列拖拽排序）
 · 不要用 Material Symbols 字体图标 —— 实现是自绘 24×24 线稿（stroke 1.7），
   请直接画成线稿，否则我们还要一比一翻译
```

## 二、附录 A：完整状态表（验收依据）

> 「文案」列是**现在代码里真实在用的字符串**，可以直接改措辞，但语义不要变。

### A-1 我是接收方

| # | 内部状态 | 现有文案 | 主按钮 | 次按钮 | 进度 | 说明 |
|---|---|---|---|---|---|---|
| 1 | `invited` | 等待你确认 | ✓ 接收 | ✗ 拒绝 | 无 | **最高频的一屏**。接收会弹出系统保存位置对话框 |
| 2 | `active` | 传输中 | — | ✗ 停止 | 有（块进度） | 停止后**已收内容保留**，之后能继续 —— 文案里必须体现 |
| 3 | `paused` | 已暂停（可续传） | ↻ 继续接收 | — | 有（停在中途） | 网络断了 / 用户主动停 |
| 4 | `interrupted` | 接收中断（可继续） | ↻ 继续接收 | — | 有（停在中途） | 刷新或关页后恢复出来的，和 3 是同一件事的两个来源 |
| 5 | `cancelled` | 已取消保存（可重新接收） | ↻ 继续接收 | — | 有 | |
| 6 | `asking` | 正在联系发送方… | — | — | 无 | 点了历史卡片之后，等对方重发邀约 |
| 7 | `done` | 已完成 | — | — | 满 | **不要画"打开文件"** |
| 8 | `rejected` | 已拒绝 | — | — | 无 | 中性色，**不要用失败红** |
| 9 | `failed` | 失败：<原因> | — | — | 无 | 红。重试入口在**发送方**那边 |
| 10 | `expired` | 已失效 | — | ✗ 移除 | 无 | 只删本端记录 |
| 11 | `archived` + `avail=live` | 可接收（发送方在线） | ✓ 接收 | — | 无 | 点它会请对方重发一份邀约 |
| 12 | `archived` + `avail=unknown` | 检查中… | — | — | 无 | 短暂中间态 |
| 13 | `archived` + `avail=expired` | 已过期（发送方已离开） | — | ✗ 移除 | 无 | |

### A-2 我是发送方 · 单接收者

| # | 内部状态 | 现有文案 | 按钮 | 进度 | 说明 |
|---|---|---|---|---|---|
| 1 | `pending` | 等待对方确认 | — | **不画总进度条** | 已被用例钉死 |
| 2 | `active` | 传输中 | — | **不画总进度条** | 只显示状态文字 |
| 3 | `sent` | 已发送，等待对方确认 | — | 不画 | 数据发完、对方校验中的空窗期。**必须和"传输中"分开**，否则大文件看起来像卡住了 |
| 4 | `done` | 已完成 | — | 不画 | |
| 5 | `failed` / `expired` | 失败：<原因> / 已失效 | ↻ 重新邀请 | 不画 | 只在**有人失败或取消**时出现 |
| 6 | （`available=false`） | 已停止分享 | **无按钮** | 不画 | 文件被内存预算淘汰。别画"停止分享"按钮 |

### A-3 我是发送方 · 多接收者 ★

**汇总行**（拼成一行，顺序固定）：

```
已分享 | 已停止分享
  · N 人接收完成 · N 人接收中 · N 人等待接收 · N 人拒绝接收 · N 人取消接收 · N 人接收失败
  · （若还"已分享"且没有任何人处于 完成/接收中/等待 状态）等待接收
```

**接收详情**（可折叠，`接收详情（N 人）`）：

| 个人状态 | 现有文案 | 进度条 | 错误说明 |
|---|---|---|---|
| `waiting` | 等待接收 | 无 | — |
| `sending` | 接收中 42%（100% 时显示"等待确认"） | **有，每人自己的** | — |
| `done` | ✓ 已接收 | 无（或满） | — |
| `rejected` | — 已拒绝 | 无 | — |
| `cancelled` | — 已取消 | 无 | 有（可展开） |
| `failed` | 接收失败 | 无 | 有（可展开） |

每行显示 `昵称 · id前6位`（没有昵称时显示 `用户 id前8位`）。

### A-4 图片卡 vs 文件卡

| | 图片卡 | 文件卡 |
|---|---|---|
| 宽 | 220px | 280–380px |
| 主体 | 图片；未接收时 116px 占位框（含文件名） | 文件类型图标 + 文件名 + `大小 · 我发送/对方发送 · 状态` |
| 进度 | 有（3–5px 细条） | 有（接收方向）；发送方向隐藏 |
| 底部 | 状态 + 大小 + 按钮行（小号文字按钮） | 状态在 meta 行；按钮是右侧圆形 ✓ / ✗ / ↻ |
| 特例 | 预览已释放 → 「图片预览已释放，文件仍保存在本地」 | 有错误时的红色说明行 |
| 点击 | 打开全屏大图查看器（点任意处 / Esc 关闭） | — |

### A-5 按钮形状（现状）

- 图片卡底部：小号**文字**按钮（接收 / 拒绝 / 继续接收 / 停止 / 重新邀请 / 移除）
- 文件卡右侧：**圆形图标**按钮（✓ / ✗ / ↻），直径 30px
- 发送方「重新邀请」：圆形 ↻（图片卡上是文字"重新邀请"）

## 三、附录 B：这些能力**现在没有**，所以别画

| 别画 | 原因 |
|---|---|
| 传输速率（MB/s）、剩余时间、ETA | 没有速率估算 |
| 排队位次、"第 2 个传输" | 没有队列概念；传输是逐个发起、独立进行的 |
| 断点续传的"精确到第几块/秒"控件 | 续传是自动按已收位图补块，用户只需要一个"继续接收" |
| 「打开文件」/「在文件夹中显示」 | 保存后不持有文件句柄 |
| 「停止分享」按钮 | `available=false` 是系统行为（内存预算淘汰），不是用户操作 |
| 多文件选择后的队列排序 / 拖拽调整顺序 | 待发送区是"逐个移除 + 一起发送"，没有排序 |
| 语音消息条 | 这个功能决定不做（另见改造报告） |
