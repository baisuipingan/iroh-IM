# 2026-10-12 R1：@ 按 id 寻址（昵称只给人看）

## 一句话

@ 从"按昵称找"改成"**按 EndpointId 找**"：线上/历史里存的是规范 token `@<id8>`，
昵称只在两处出现 —— **输入时给人挑**、**渲染时给人看**。

## 之前错在哪（按昵称 @ 的三种坏法）

| 场景 | 按昵称 | 现在（按 id） |
|---|---|---|
| 房间里有两个"小助手" | 谁先匹配到算谁，常常 @ 错人 | token 只指向一个 id，**不会认错** |
| 某人改了昵称 | 历史里的 `@旧名` 永远指向"查无此人" | chip 显示**新名**（渲染时才查名册） |
| 昵称为空 / 重名且对方离线 | 直接 @ 不到 | 仍指向那个 id（查不到就显示 id8，不猜） |

## 规范（写进 `docs/agent-as-member-plan.md` §4 R1）

- **规范 token**：`@<id8>`，`id8` = EndpointId 前 8 位小写 hex。
  放文本里而不是结构化字段：结构化 `mentions` 要改签名载荷（破坏性）⇒ 留 v6。
- **解析三规则**：
  1. `@` + 8 位 hex ⇒ 提及；按 id8 在当前房间名册里唯一匹配；
  2. 匹配不到（离线/换房）⇒ 渲染成 `@<id8>`（虚线圈），**不报错**；
  3. 裸 `@昵称` **不作为寻址依据**；但**发送前**解析一次：唯一匹配 ⇒ 换成 token；
     同名歧义或无匹配 ⇒ **原样当普通文本**，并给用户一句可见提示。
- **边界**：`@` 必须是行首/空白/常见标点之后，`a@b.com` 这种邮箱不会被误当成提及。
- **agent 侧**：认领 = `@<自己的 id8>`（`client.hello.endpointId`）；昵称匹配只作兼容兜底。

## 顺手挖出并修掉的一个真 bug

**"@ 我"的 chip 有时会显示成别人的名字**：渲染 chip 时"我自己"的名字取自
`store.nick()`（localStorage 偏好），而一个浏览器开多个标签时 localStorage 是**共享的** ——
另一个标签刚改的昵称会顶进来。新增 `net.myNickname()`（= 我**进房时广播出去的**名字，
权威）并改用它。这是被测出来的，不是猜的。
