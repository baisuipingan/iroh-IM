# 2026-10-13 前端常驻负载优化：聊天页不再"永远 60fps 出帧"

## 一句话

把聊天页里两处**只要开着就永远跑 CSS 动画**的效果（7 颗环境气泡、在线光点脉冲）
改成 **~12fps 的画布绘制 + JS 相位驱动**；头部那条模糊的背景改成静态可缓存。
**视觉不变**（同样 7 颗、同一条上浮路径与淡入淡出；圆点照旧脉冲），
本机实测常驻 CPU（软件合成）**28% → 13%**。

## 为什么（机制）

浏览器只要还有**一条 CSS 常驻动画**在跑，就会**永远以 60fps 出帧** —— 每帧都要
合成整个窗口（叠上每帧重绘的 box-shadow 脉冲、每帧重算的 `backdrop-filter`）。
苹果 M 系芯片功耗低、风扇少，感知不到；**老 Intel Mac 上就是"开着聊天页风扇狂转"**
（2026-10-13 用户报障：M3 上无感、Intel 机器上风扇声特别大）。主线程 JS 几乎不干活
（TaskDuration 0.6s/15s），烧的全是合成/重绘。

## 改了什么

| 位置 | 之前 | 现在 |
|---|---|---|
| 环境气泡（`.ambient__b` ×7） | 7 个 DOM 元素各跑一条 CSS `floatUp` 动画（无限、compositor 常驻） | `motion.js` 用**一张画布按 ~12fps** 画 7 颗；关键帧（0/15/50/85/100%）与 `ease-in-out` 缓动**逐项搬进 `floatUpAt()`**；窗口不可见/失焦即停画 |
| 在线光点脉冲（顶栏药丸 + 房间行圆点） | 对 dot 自己 `box-shadow` 动 `radarPing`（无限、**box-shadow = 每帧重绘**） | 伪元素环（只 `transform`/`opacity`），相位由 JS 每 ~83ms 写 `--ping`（0→1）；`--ping` 缺省 1 = 环不可见 |
| 头部 `.chat-head` 的 `backdrop-filter` | 气泡从头部后面穿过 → 背景每帧在变 → **每帧重算 12px 模糊** | `.ambient` 裁到头部下缘（气泡本来就被 90% 不透明的头部盖住、看不见）→ 模糊背景变静态 |
| `prefers-reduced-motion` | `.ambient` 隐藏 | 不变，另加：两个 JS 定时器都不启动 |

`floatUp` / `radarPing` 两个 keyframes 已删除，并就地留了"别加回来"的注释。

## 实测（本机 Chrome headless，`--disable-gpu` 软件合成）

> 说明：测量环境是**软件合成**，绝对值比真机（GPU 合成）高；相对改进才是要看的。

| 场景 | 整棵 Chrome 进程树 %CPU | GPU 进程 |
|---|---|---|
| 改造前（基线） | **27.9 ~ 28.1%** | 22.0 ~ 23.4% |
| 对照：只去掉两个脉冲 | 22.8% | 18.8% |
| 对照：脉冲+气泡都去掉（地板） | **0.8%** | 0.1% |
| **改造后** | **13.2%** | 8.7% |

- 对照实验证明"两条常驻动画 = 常驻 27% 的合成循环"，去掉即掉到地板。
- 改造后剩下的 13% 是"12fps × 整窗合成"的底价（软件合成下）；真机 GPU 合成会低得多。

## 回滚

前端：回退上一 CF 版本（或 `git revert <本提交>` 后 `bash scripts/deploy-web.sh`）。
纯前端改动，roomd / wasm / agent 二进制均未动。

## 如果 Intel 机器上还响（下一步备选，按侵入度排序）

1. 把气泡数从 7 降为 3~4（`motion.js` 的 `BUBBLES` 常量删几行即可，视觉略简）；
2. 打开系统"减少动态效果"（气泡整层关掉，是最省的一档）；
3. 继续降画布帧率（`1000/12` → `1000/8`）。

## 反漂移自检（方案 §8 逐条）

1. **房间只是场地**：是 —— 纯渲染层改动，协议/房间模型零变化。
2. **@ 只按 id 寻址**：是 —— 不涉及。
3. **加 agent = 加 spawn 配置**：是 —— 不涉及。
4. **可单独回滚**：是 —— 前端单文件回退即可。
5. **决策与现实冲突**：无。所有者要求"不改变现在效果"，为此**逐项保留了原关键帧参数**
   （尺寸/位置/时长/透明度/缓动全部照搬），只换了执行方式与帧率。
