# 2026-10-12 两修：服务器助手停收文件 + 传文件时的"成员频繁退出又进来"

## 一句话

①**服务器助手不再接收文件**（`--files off`）：所有者要求"先不做发文件给 agent"；
②修"传输大文件时房间里成员频繁退出又进来"：**传输在途时 presence 的掉线判定放宽到 3×、
心跳提速到 3s，并且任何验签通过的帧都算"他还活着"**。

## 问题①：发文件为什么会被服务器助手自动接收

不是被 @ 触发的 —— 是那个常驻 agent 的**文件策略开的是自动接收**
（`--files accept --files-max-mb 64 …`）：房间里任何人发文件，它都会收下并落盘
（实测：`/opt/iroh-agent/received/` 里 10-12 当天落了 4 个文件，共 ~17 MB）。

**修法**：线上 unit 与仓库 unit 都改成 `--files off`（只记日志、不接收也不拒绝）。
旧 unit 已备份为 `/etc/systemd/system/iroh-agent-pi.service.bak-<时间戳>`；
重启后日志：`已就绪：… files=off`。存量收到的文件**没有删**（在
`/opt/iroh-agent/received/`，要不要清理由所有者定）。要开回来见
`deploy/agent/README.md`「运维」表与 unit 里的注释。

## 问题②：传输文件过程中"退出聊天室然后又进来"

### 证据与机制

- 服务器侧证据：15:41–15:47（CST）收到 4 个文件（其中同一文件发了**两次** —— 与
  "传着传着断了要重发"一致）；**agent 进程全程没有重启**（不是它掉线重进）。
- 基线：本地把房间静置 **6.7 分钟**，presence 零变化 —— 不传输不会闪。
- 机制（强支持，非百分百钉死）：该房间是 **relay-only** 的慢上行
  （26 MB 传了 ~6 分钟 ≈ 70 KB/s），链路被打满时**心跳会被拖过默认 35s TTL**，
  于是双方互相把对方判成"掉线"→ 再收到下一条心跳又"回来" → 界面上就是
  **成员反复退出又进来**。presence 本来就是软状态（晚判一会儿没有正确性代价）。
- ⚠️ 为什么没钉死到最后一帧：能证明真相的 roomd 日志当晚被容器重建带走了
  （它记心跳到达时刻）；本地网络太快（9 MB ≈ 12s），复刻不出慢上行。
  所以修法是**按机制做对鲁棒性**，并把判据留在代码注释里。

### 修了什么（三处，都在传输与 presence 的交互上）

1. **传输活动信号**（`transfer_orchestrator.rs`）：发/收每块数据都刷新
   `LAST_TRANSFER_ACTIVITY_MS`（一次原子写）。
2. **传输在途 ⇒ 掉线判定放宽到 3×**（`room.rs::effective_presence_ttl`）：
   最后一块数据之后 60 秒内，成员 TTL 35s → 105s（客户端与快照/服务端新鲜度检查
   同规则）；静默 60 秒后自动恢复原值。
3. **传输在途 ⇒ 心跳提速 10s → 3s**；并且**任何验签通过的帧**
   （消息 / 文件控制 / 可用性质询 / 名片帧）都刷新该成员的 `last_seen_ms`
   （`touch_peer`）—— 心跳被拖住时，别的帧同样是"活着"的证据。

### 已知边界（如实记）

- 常驻节点（roomd）没有自己的传输活动，第三个观察者（比如刚进房的人看快照）在
  超长上传期间**仍可能**短暂看不到上传者；这是软状态语义，不在本次修的范围。
- 服务器上的 agent 二进制仍是 Release `agent-v1.3.0`（本次 Rust 改动对它的职责
  无影响；要让它也拿到这套逻辑，下次发 agent Release 时自然带上）。

## 回滚

- 单元：`cp /etc/systemd/system/iroh-agent-pi.service.bak-<时间戳> …` + `daemon-reload` + 重启
- 前端：回退上一 CF 版本（或 `git revert <本提交>` 后 `deploy-web.sh`）
- **roomd / agent 二进制本轮未动**（roomd 读到的传输信号恒为 0，行为零变化，故不重发；
  agent 二进制不受影响）。

## 反漂移自检（方案 §8 逐条）

1. **房间只是场地**：是 —— 没有新增房间级登记，只是把"成员是否还活着"的判定做稳。
2. **@ 只按 id 寻址**：是 —— 不动寻址。
3. **加 agent = 加 spawn 配置**：是 —— 文件策略就是 unit 里一个 flag。
4. **可单独回滚**：是 —— 见上，三处独立。
5. **决策与现实冲突**：无。所有者明确"暂时不做发文件给 agent"，已按此执行并留了开回路径。
