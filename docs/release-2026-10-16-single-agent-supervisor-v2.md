# 2026-10-16 room-bridge 进程级身份锁与重启竞态修复（bridge 0.2.7）

## 根因复盘

0.2.6 修复了同一个 `AgentClient` 内部重复启动 `iroh-agent serve` 的问题。现场仍需要补上两层保护：

- 旧版本桥已经在同一身份目录下留下多个 `serve`，新桥无法从网络层自动区分并清理它们；
- 同一身份目录可以被用户手动启动两份 `room-bridge`，两份进程会再次共用 `identity.key`；
- 重启中的 `serve` 可能在刚输出 `hello` 后立即退出，退出事件发生在重启循环完成前时，下一次重启请求不能丢；
- 停止桥时，重启循环的握手等待不能继续占用最长 60 秒的定时器。

## 修复

- `IROH_AGENT_HOME/.room-bridge.lock`：同一身份目录只允许一个 bridge；锁记录 PID 和 token，正常退出释放，遗留锁会按进程存活状态回收；
- 握手失败会杀掉对应的 `serve`，协议版本不匹配不会留下后台进程；
- 重启循环记录并补跑并发退出请求，确保恢复成功后不会静默失联；
- `stop()` 主动取消握手等待，服务管理器重启/退出不再无意义等待 60 秒。

## 验证

- `agent-pi` TypeScript 类型检查通过；
- AgentClient 稳定性测试覆盖：连接看门狗、全断提前重启、单实例启动、握手前退出、握手后立即退出、正常连接不误杀；
- 进程锁测试覆盖：重复启动拒绝、释放后重启、损坏锁文件恢复；
- Release 二进制真实进房补投 e2e：桥离线期间被 @，重启后补投并回复一次，二次重启不重复；
- 发布前会清理旧版 `room-bridge` 下累积的 `iroh-agent serve`，确认运行态为一桥一腿。
