# 2026-10-12 R2a：名片 = 签名消息 + 本地聚合

> 这是 R2 的前半：**客户端侧**完整可用。后半（常驻节点把名片聚合进房间快照）
> 记为 **R2b**，见文末"还没做"。

## 一句话

成员给自己写一份**名片**（简介 + 标签）。它是一条**普通的签名消息**，
天然进历史；客户端从消息里学到名片并持久化。于是"这人能干什么"就看三样东西：
**名字、简介、他在这房间说过的话** —— 不需要任何"工具清单"。

## 为什么是"签名消息"而不是新协议帧

新增协议帧要改 `ChatMessage` 的**签名载荷** = 破坏性变更（决策②/③）。按计划，
正式的房间状态帧留到 v6；现在用"约定格式的签名消息"落地，**语义完全一样**，
而且顺带拿到两个好处：**可验签**（谁写的骗不了）、**天然进历史**（新人翻记录就看到）。

## 格式（**唯一实现**在 `frontend/js/profile.js`，别处不许手拼）

```json
{"t":"profile","v":1,"bio":"能查代码 · 会跑脚本","tags":["ts","rust"]}
```

- **键序与空白是约定**：必须是 `{"t":"profile"` 前缀且无空格 ——
  常驻节点将来要能一句 SQL 认出它们（R2b：`text LIKE '{"t":"profile"%'`）。
- 上限：简介 160 字、标签 ≤8 个（每个 ≤16 字）；换行会被压成空格。
- 坏 JSON / 不是名片：`parseProfile` **返回 null 且永不抛**（一条脏消息不该打断时间线）。
- **只认更新的那条**（按 `ts`）：gossip 不保证顺序，重放旧名片不该把新简介盖回去。

## 顺手挖出并修掉的一个真 bug

**自己改完名片，自己看不见那行提示**（对方却收得到）：`editMine` 直接调 `net.send()`，
而"自己发的消息"的本地回显是 **composer** 那条路径 emit 的 —— 少了它，自己的时间线要等
下次重新拉历史才出现。修法与 composer 一致：发完补一条 `EV.MSG`（`mine: true`）。

### 关于整轮 4 次的如实记录

| 轮次 | 结果 | 单跑复核 |
|---|---|---|
| 1 | `redesign` 报「设置项说明文字折行」 | **真回归**（我新加的那行说明太长）→ 缩短 + 截断取值 → `redesign` **127/0** |
| 2 | `diagnostic-probe` 等诊断页上线 45s 超时 | 单跑 **22/0** |
| 3 | `file-recipients` 8 MiB 传输停滞（CRASH） | 单跑 **34/0** |
| 4 | `redesign` 卡在「进房」超时（页面没进房） | 单跑 **127/0** |

共性：失败都是 **CDP/启动/吞吐类的超时**，不是断言失败；同一改动下**每次抖的套件都不一样**；
都与本次改动无关（图片版式、文件吞吐、诊断页上线、页面进房 —— 没有一条走 @ 或名片那条路径）。
本机 16G、空闲内存只剩 ~120~500MB，且同时跑着用户自己的 Chrome / 微信 / OrbStack —— 
仓库在 2026-10-10 的发版记录里已经记过同一现象。**新增的三个用例
（`profile` 11/11、`mention-id` 18/18、`plugin-channel` 11/11）在 4 轮整跑里每次都全绿。**

## 还没做（R2b，下一期）

常驻节点把名片**聚合进房间快照**（`MemberSnapshot` 加 `bio`/`tags`，从历史里学），
这样"翻页翻不到的老名片"也能被新进房的人立刻看到。今天的行为是：
**名片在最近一页历史里 → 立刻看到；更早的 → 暂时看不到**（客户端只从它加载到的消息里学）。

## 反漂移自检（方案 §8 逐条）

1. **有没有让"房间只是场地"变差？** 没有：名片是**成员自己发的消息**，不是房间登记的"清单"。
2. **有没有把昵称当寻址依据？** 没有：名片按 `from`（EndpointId）索引，昵称只是显示。
3. **新增 agent 接入要不要改房间侧？** 不需要：agent 想报名片，只要发同样格式的一条消息。
4. **能不能单独回滚？** 能：纯前端，切回上一个 CF 版本即可。
5. **有没有已拍板决策与现实冲突？** 有一处**范围**问题已按计划处理：计划里 R2 写着
   "快照聚合"，本期只做了客户端侧（R2a），**没有静默缩小范围** —— 记在台账与本文的"还没做"里。
