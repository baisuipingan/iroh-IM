## 修复范围

| 原问题 | 处理 |
|---|---|
| F01 超长消息假成功 | 前端限制文本 UTF-8 64 KiB，原文和附件保留；Rust 在广播前检查完整签名 JSON 的字节数，并给底层协议头预留预算。超限报文不进入 gossip 队列。 |
| F02 同身份刷新重进失败 | 修复 HyParView 旧 Neighbor 握手去重吞掉新 Join 回复的问题。锁定并 vendor `iroh-gossip 0.101.0`，仅对该成员重置未完成握手；提供失败后的“重新进入”按钮。 |
| F03/F04 草稿丢失和串房 | 发送采用文本/附件快照，仅移除成功发送的附件；不覆盖发送期间输入的新文本或新附件。内存草稿按房间保存，刷新不保留。 |
| F05 取消保存无法重邀 | 接收端区分 cancelled 与 rejected，取消者可再接收/重新邀请，明确拒绝者不再打扰。 |
| F06 WebKit接收锁死 | 不支持保存 API 时不提供接收按钮，明确 Chrome/Edge 要求并保留拒绝/移除；选择保存位置异常后恢复控件。 |
| F07 房名过长超时 | UI、网络入口、Rust 加入入口统一 1–256 UTF-8 字节及禁止控制字符的规则；非法名不保存、不请求网络。 |
| F08 本地删除不持久 | 按房间/消息 ID 保存隐藏标记，历史补齐和刷新时过滤；不删除服务器或他人消息。 |
| F09 图片无预览 | 原文件经 P2P 保存后提供本地缩略图及放大查看。仅 PNG/JPEG/WebP/GIF、文件 ≤8 MiB、解码后 ≤16M 像素；缩略图最大1024px，最多保留20张并回收旧blob URL。原始文件不再广播为base64，超大/无效图片仍作为文件保存。 |
| F10 未读模型落差 | 保留单当前房订阅设计，明确通知范围；当前房隐藏标签页收到实时消息累计未读，返回时清除。没有新增其他房间后台订阅。 |
| F11/F12 身份与隐私误导 | 公开ID不再称作主密码；说明私钥才需保密、常驻节点保存可读取的历史、知道房名即可访问。没有新增历史鉴权或成员审批。 |
| F13 房间上限丢置顶 | 第41间明确提示上限，不静默替换已有房间；菜单支持复制真实房名、移出列表并退出当前房。 |
| F14 清理不同步 | 清理前退出当前房、丢弃草稿；即时应用默认偏好，保留身份和服务器历史。 |
| F15 存储失败启动卡死 | 配置、身份和邀约存储统一安全读写；失败降级当前页面内存并明确弹出“临时存储模式”，不宣称刷新后仍保留。初始化也在启动错误边界内。 |
| F16/F17 窄屏与键盘 | 表情面板按可用宽度适配；核心入口可键盘操作；模态带语义、背景inert、Tab循环和关闭后焦点恢复。 |
| F18 空文件静默丢弃 | 明确说明零字节文件暂不支持。 |
| F19 回归假绿 | 保留真实子进程退出码及FAIL/CRASH；未知或缺失用例非零退出；文件失效等待改为协议一致的状态轮询上限。 |

同时保留此前按接收者独立统计文件结果的未部署修改。语音仍未实现，入口明确禁用；
昵称按可见字符计数；本地占用改称“本地配置占用”；发送快捷键说明随设置更新。

## 根因与隔离验证

- 生产旧节点日志确认持续收到同 EndpointId 的 Join，却没有新 Neighbor 回复；单纯强制建立新 QUIC 连接不能解决，因此撤回该临时尝试。
- 新增 `client-wasm/tests/gossip-rejoin.rs`：未修补版本第二次 Join 必然失败，修补后连续三次无回执的 Join 都获得回复。
- 在服务器启动独立测试容器 `roomd-review-20261004`，使用独立身份和数据目录；测试浏览器覆盖锚点配置，不先重启生产。
- 隔离节点同身份连续刷新三次恢复，首次定向实测分别约 1.15/1.33/1.60 秒；后续高负载回归也出现过约23秒的首轮重试，不承诺每次都瞬时连接。
- 快速重进还揭示恢复邀约的竞态：初始成员快照不完整不应立即永久删除邀请。增加30秒成员心跳宽限，再判定离线。

## 线上复测追加修复

首轮线上定向42项通过，但扩展多端回归暴露了两个额外边界；失败日志保留在
`output/playwright/fix-online-suite-logs/`，没有把这轮标成全部通过。

- 启动等待：原来只等待 Worker 的 `booted` / `boot:error`，脚本加载失败没有这两种消息，
  页面会永久“启动中”。阻断 Worker 下载实际复现后，增加 Worker 错误处理、45秒启动上限、
  失败时终止 Worker 和重试入口；中继配置请求也有15秒可取消上限，失败仍可回落本地缓存。
- 文件证明/邀约乱序：实时签名文件证明先于邀约抵达时，会先创建 `archived` 卡片，
  随后的新邀约被防历史广播串扰守卫吞掉。区分实时证明和历史证明，前者允许新邀约接管，
  后者仍保持历史卡片，不让其他人的查询劫持。未改签名或线上报文。
- 扩展文件用例不再假定历史补齐一定晚于实时邀约。若收到可接收的历史卡片，
  会实际请求发送方补齐邀约，再验证接收和文件字节；不把“出现历史卡片”直接算作接收成功。
- 新增8个定向断言：实时证明先到、历史旁观卡不被劫持、Worker加载错误、Worker无启动响应、
  两类启动失败后的实际按钮重试，以及配置超时的有缓存/无缓存路径。
  本地最终定向50项全部通过；故障与报文顺序使用明确注入，不冒充自然发生的网络故障样本。
